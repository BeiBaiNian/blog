星记 XingJi：端到端加密的双端备忘录，从需求拆解到双端交付

  • 2026-11-23
  • 作者 董子阳
  • ~4.19K 字

这是我从 0 到 1 独立完成的一款私人备忘录：Windows 11 桌面端 + Android 手机端，同一套业务代码，断网照常写，联网自动对齐，服务器上只有密文。

起因很具体。我想把日记式的待办、家里的事、工作上的碎念放在一个地方，但不愿意它们以明文躺在别人的数据库里，也不愿意哪天断网就什么都写不了。于是做了这个项目，并且在三条约束下反复砍功能——不上云、不丢数据、不装死。

项目从 0.3.0 迭代到 0.5.1，首方代码约 15 400 行，最终交付了 Windows 安装包、Android APK 和一份自建 PostgreSQL 同步后端。这篇按「需求 → 产品 → 方案 → 落地 → 交付」讲，技术细节放到文末的专栏里，这里只讲为什么这么设计、代价是什么。

💡 需求：三个「不」

大部分备忘录不缺功能，缺的是「敢把真话写进去」的底气。我把需求压成三句话，每句话都直接决定了一条产品原则：

用户的顾虑 具体要求 由此定下的原则
我的私事不想被平台看见 内容不能以明文存在服务端，DBA 直读也拿不到 端到端加密，服务端零知识
地铁、飞机、服务器挂了也不能丢 没有网络、没有服务器也必须完整可用 离线优先，本机是主副本
设了提醒就必须响，没响要能查 不能「发出请求就当成功」 提醒可靠性优先于功能数量

还有一条隐性需求：不想注册账号。所以同步不走第三方云，用户自己部署一个 PostgreSQL，两端连同一个库就行——没有账号体系、没有遥测、没有「登录后才能用」。

核心用户旅程一行能写完：建资料库（设主密码、存恢复码）→ 记事 → 设提醒 → 到点提醒 → 完成归档 → 按日期回顾 → 双端同步 → 导出加密备份。

目标用户是三类人：注重隐私的个人；电脑上批量整理、手机上到点提醒的双端用户；有 NAS 或 VPS、愿意自己跑一个库的自建用户。

🎯 产品定义：做什么，不做什么

需求清楚之后，功能取舍反而容易。这一版交付的能力：

能力 桌面 手机 说明
事项：标题 / 正文 / 标签 / 清单 / 优先级 ✅ ✅ 标题 200 字、正文 20 万字、清单 100 项
到期提醒 + 提前 N 分钟多档 ✅ ✅ 桌面 512 条、手机 480 条预排
重复：每日 / 每周 / 工作日 ✅ ✅ 完成本次归档，自动排下一次
稍后提醒 / 完成 / 结束重复 ✅ ✅ 通知按钮直达，锁定状态需先解锁
夜间静默（22:00–08:00） ✅ ✅ 普通提醒顺延到 08:00，事项级闹钟例外
事项级「闹铃提醒」 — ✅ 调系统时钟 1 秒倒计时
完成归档 + 按日期回顾 ✅ ✅ 三种日期基准 × 三种状态
编辑历史（每条 30 版）+ 预览恢复 ✅ ✅ 只有显式保存才留版本
回收站 + 永久删除（防复活） ✅ ✅ 需服务端结构 v2
本机加密图片（≤ 9 张/条、≤ 500 MiB/库） ✅ ✅ 不同步、不进备份
双端同步（自建 PostgreSQL） ✅ ✅ TLS 默认校验证书，可导入 CA
加密备份导出 / 导入（.xingji） ✅ ✅ 含回收站与历史
托盘常驻 / 随登录启动 / 全局热键 ✅ — 关闭即退出，最小化进托盘

刻意不做的：不做云账号与分享协作（等于放弃云端明文，产品定位不同）；不做自动更新通道（要签名与分发基础设施）；图片这一版不做跨端同步（原因见「边界」一节）。

🧭 整体方案：一套业务层，两套壳

确定了「双端一致 + 服务端不可信」，架构几乎是推导出来的：

  • 一套 Dart 业务层同时喂两端。界面按设备选一次布局，状态全部收敛在一个控制器里，桌面和手机不会出现「同一个功能两种行为」。
  • 平台差异全收在适配层。设备密钥保护（Windows DPAPI / Android Keystore）、文件选择、后台同步都藏在一组统一接口后面，业务层不写平台判断。
  • 加密发生在应用层之下。本机 SQLite 只存密文包，服务端只接收密文包，明文只活在内存里。
层面 选型
跨端 Flutter 3.47.8 / Dart 3.13.7，一套业务层两端复用
加密 libsodium：Argon2id 派生、XChaCha20-Poly1305、HKDF
本机存储 SQLite（WAL 模式），密文库 + 待发队列 + 历史版本
同步 自建 PostgreSQL 16，9 个 PL/pgSQL 函数即全部 API
原生 Windows：C++/WinRT + Win32；Android：Kotlin
交付 PowerShell 构建脚本族、Inno Setup 安装器、APK 签名指纹固定

🖥️ 两端体验：同一份数据，两种用法

桌面端是三栏：左边筛选、中间列表、右边详情。适合一次整理十几条、批量改标签、翻历史版本。编辑器做了防抖和串行保存，快速连续输入不会互相覆盖；只有点「保存并返回」才留历史版本，自动保存只更新当前内容。

手机端是三段导航：「今天 / 备忘录 / 日期」。默认落在「今天」，未过时和已过时分组，到期自动变灰移到末尾但不自动完成——事情没做完就该留在那儿。

⏰ 提醒：最容易被低估的需求

用户对提醒的要求只有一句「到点要响」，但这句话在真机上要过三关：系统权限给不给、厂商 ROM 拦不拦后台、时钟应用在不在。传统做法是「请求发出去了就算成功」，结果用户到点没听到铃，打开应用也查不到原因。

我的处理原则是：宁可降级，也不静默，也不虚报。

  • 排程做三级降级：闹钟级 → 精确唤醒 → 允许空闲唤醒，界面明确显示这次是「登记成功 / 已降级 / 失败」；
  • 「请求已经发给系统时钟」和「系统真的播放了」是两件事，界面上分开写，代码注释里也写清楚；
  • 失败原因拆成 8 类（权限缺失、时钟应用不存在、要用户先选默认时钟、后台启动被拒等），每条都对应一句人话提示和跳转设置；
  • 提供 30 秒 / 10 秒两档自测和「复制最近 10 条诊断」，真机排障才有抓手。

另一处取舍是免密期固定 72 小时，打开应用不续期。方便和安全总要选一边，这里选择让「临时解锁」有明确的有效期，而不是打开一次就永久免密。

🔐 隐私承诺怎么兑现

「服务端看不到内容」不是一句口号，它由两个具体机制撑着。

一是密钥分层。主密码经慢哈希派生出的密钥只用来解开「包装密钥」，再由包装密钥解出资料库密钥；恢复码是另一条独立入口。改主密码只重包这一层，不换资料库密钥——所以旧密码立刻失效，但旧备份仍然打得开。

二是删除要真的删。只打一个「已删除」标记是拦不住内容回流的：离线设备的旧副本、用旧备份恢复、重试请求重放，任何一条都能把内容写回来。所以删除被设计成一条「认证过的空密文」替换所有版本，服务端把它在变更流里的历史密文一并置空，其余设备拉到后先认证标记再本地擦除。

那服务端到底能看到什么？记录条数、记录 ID、密文长度、同步游标、写入时间、设备 ID。看不到标题、正文、标签、清单，也看不到「这条什么时候到期」——时间是密文里的字段。这条边界我写在文档里，不夸张也不藏。

🧪 交付与质量：一个人的项目也得能复现

独立开发最怕「只有我这台机器能构建」。所以这一版把交付当成功能做：

  • 双端产物：Windows 安装包 12.25 MB、便携 ZIP 11.78 MB、Android APK 63.48 MB（ARMv7 / ARM64 / x86_64 三架构），外加 SHA-256 清单、使用说明、第三方许可证声明。
  • 构建可复现：PowerShell 脚本族把环境隔离、依赖解析、编译、打安装包、生成清单串成一条链；构建用独占锁做租约，并发构建不会互相踩临时目录。
  • 升级不丢数据：APK 构建后自动比对签名指纹，和发布时固定的一致才允许出包——签名一换，覆盖升级就会让用户丢数据。
  • 回归可追溯：76 个用例分 11 个文件，其中 5 项需要独立 PostgreSQL 的集成用例默认跳过；另有 Android 仪器测试和 Windows QA 夹具，验收证据按版本留档。

🚧 边界与取舍

  • 没做：完整月历视图、自动更新、完整密钥轮换、跨设备本机历史同步、图片跨端同步、非空资料库的切换与合并。
  • 已知取舍：SQLite 整库没有加密（只加密业务字段），运行元数据可见；永久删除不清 WAL 与磁盘快照；服务端会保留删除标记的元数据行。
  • 没验证：Android 真机的厂商后台策略（Redmi K60 仍待测）、实际扬声器响度、Android 14+ 的后台启动限制；Windows 安装器没做商业代码签名，首次安装会触发 SmartScreen。
  • 为什么图片不同步：500 MiB / 库的体量，跨端同步要分块上传、断点续传、配额协商和失败回滚，做半套比不做更危险。这一版先把「本机加密 + 引用回收」做对。

📚 技术细节去哪了

上面每一段背后都有一堆实现细节，全塞进来会让这篇变得没法读。我把它拆成几篇单独写，写完在这里挂链接：

  • 《密钥模型：为什么改密码不用换密钥》——自认证密钥包、AAD 绑定、恢复码
  • 《9 个 PL/pgSQL 函数撑起的同步协议》——行锁与游标、幂等、乐观锁与冲突副本
  • 《提醒为什么会「没响」》——Android 三级降级、系统时钟交接与 8 类失败原因
  • 《图片：分块认证与引用回收》——HKDF 分密钥、256 KiB 分块、触发器回收

做这个项目最大的收获不是用了多少密码学原语，而是学会把「不知道」和「做不到」写进产品和文档里：服务端确实看不到明文，但能看到条数；删除确实不会复活，但 WAL 里还有影子；提醒确实尽力了，但厂商拦截时只能降级并告诉你原因。把边界讲清楚，比多做一个功能更值。
